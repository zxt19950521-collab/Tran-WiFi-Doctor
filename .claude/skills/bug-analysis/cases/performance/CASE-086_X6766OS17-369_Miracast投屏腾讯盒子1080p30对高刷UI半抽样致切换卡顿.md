# CASE-086: Miracast 投屏腾讯极光盒子切换卡顿——volcano 1080p30 对高刷 UI 半抽样 + VDS 时延（非 WiFi）

- **复现机**: X6878（同 volcano/wcn6450，同盒子，同样卡顿且更重）

## 现象描述
- X6766（`X6766-17.0.0.032SP01`，volcano / wcn6450）本地 Miracast 到**腾讯极光盒子**，已连接后**切换界面 / 横竖屏**电视跟手差
- X6878（`X6878-17.0.0.038SP01_UD`，同平台）同盒子复现；**没有横屏**，桌面滑动同样卡，且尖峰更重
- P2P/RTSP **不断开**；手机为 P2P GC，盒子为 GO
- 日志：`\\10.205.4.20\sw_log\通信测试Log\X6766\qing.fang1\X6766OS17-369`

## 根因结论
**WFD Source 协商 1920×1080 H.264 ~30fps，本机 UI/VirtualDisplay 却按 ~60fps 出帧。切换界面、滑动、横竖屏使 Display 突然变快，编码器跟不上 → 队列 stuffing，电视侧跟手差。属 volcano/wcn6450 平台级 Source 问题，不是 WiFi 驱动、不是 SF 合成、不是断连。**

Source 流水线：`画面 → Display 出帧 → H.264 编码 → Mux 打成 MPEG-TS → 空口 RTT → 盒子上屏`。WFDMMSRCSTATS 的 Mux 只覆盖**编码完成之后、RTP 发出之前**的打包。

两机卡在不同段、同机理：
- **X6766 卡在编码**：11:12:44 横屏 Max Encode **62ms**，Mux 仍 **11ms**，RTT **17ms**
- **X6878 编码和 Mux 一起堵**：17:46:01 桌面滑动 Max Encode **974ms**、Mux **1039ms**（`MUX is holding all the buffers`），RTT 只到 **41ms**；编码器累计 drop=26 帧

静态画面两边 Display/Encoder 都会掉到 0（停采，不是管道坏了）。一切换/滑动，Display 拉到 60~119，Encoder 仍锁 30，再叠加 Encode 尖峰就是可感知卡顿。X6878 无横屏也卡，触发条件是**界面内容变化**，不限于旋转。

## 排查步骤
1. **先排除断连和空口**：
   - P2P-GROUP-STARTED / RTSP PLAY 之后有无 TEARDOWN、SSR
   - `WFDMMSRCSTATS` 的 Average Round Trip Time：DUT 本案全程 <30ms；即使 X6878 到 41ms 也远小于 Encode 尖峰
2. **看 WFDMMSRCSTATS 四段，不要只看 Encoder=0**：
   - Display FPS（I/P from display）vs Encoder I/P / O/P
   - Min/Avg/**Max Encode Time**（Max 是会话累计水位，抬上去不回落）
   - Min/Avg/**Max Muxing Time**（编码后打 TS；正常 Avg <2ms）
   - RTT
   - Encoder=0 且 Display 同时为 0 = 静态停采；只有 Display>0 而 Encoder 持续 0 才算 VDS 断流
3. **卡顿点对齐 UI 事件**：`requestedChangeOrientation` / `Screen config` / Launcher `ACTION_DOWN` / `TranScrollOptimizer last frame too long`
4. **有 Perfetto 时**：VirtualDisplay `presentFrameAndReleaseLayers` 帧率、SF jank_type（None vs Buffer Stuffing）。本案 SF 80% 按时，卡在 Launcher stuffing
5. **对照机**：同盒子换一台 volcano（如 X6878）。Encoder 同样钉 30fps 即可判定平台问题，不要用 RTT 谁更好来开脱

## 建议措施
1. **模块归属**：主责 WFD / Display（Source 编码帧率、VDS 时延、是否协商 1080p60）。按平台闭环，不要当单机 WiFi 缺陷
2. **高通 case**：`08743402`（video→display）。查 VDS client composition 与 30fps 编码排队，不是 SF jank
3. **编码/协商**：对极光盒子评估 1080p60，或按 Display FPS 自适应。X6878 Avg Encode 已 ~29ms（贴 33ms 预算），滑动时 Encode/Mux 约 1s，比 DUT 的 62ms 旋转尖峰更优先
4. **Encoder=0**：仅当 Display>0 而 Encoder 持续 0 才算 VDS 断流
5. **测试备注**：目录名带 `7s` 时确认观感是数秒级延迟还是短时掉帧。RTT 十几到四十毫秒远小于 7s；若确为数秒，更指向 Sink 缓冲
